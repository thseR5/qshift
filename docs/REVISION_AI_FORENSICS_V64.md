# Qshift V6.4 evaluation forensics

This report audits the historical V6.3 55-case run and the improved minimal-context rerun. It does not replace the historical result in [REVISION_AI_EVALUATION.md](/Users/eswarreddytadi/Documents/Codex/2026-11-09/referenced-chatgpt-conversation-this-is-an/docs/REVISION_AI_EVALUATION.md).

## Metric audit

The V6.3 scorer in `evals/run_live_eval.py` created sets of `(op, room, target_text.casefold())`. Its historical formulas were:

- strict TP = `|expected_set ∩ predicted_set|`
- strict precision = strict TP / `|predicted_set|`
- strict recall = strict TP / `|expected_set|`
- wrong-target rate = unmatched predicted-set items / (matched + unmatched predicted-set items)
- missing-change rate = unmatched expected-set items / `|expected_set|`

That scorer used exact room equality, no room or item aliases, exact target strings, no quantity/unit/material fields, set deduplication, and no one-to-one alignment. It therefore mixed operation-type, target, room and multi-operation errors. It also scored extraction only; deterministic line/catalogue resolution was not invoked.

The forensic scorer in `evals/forensics.py` keeps strict historical metrics and adds:

- intent-family accuracy: CHANGE, CORRECTION, CANCEL, STATUS or UNRELATED
- one-to-one maximum-weight operation alignment
- operation-type precision/recall/F1 from aligned multisets
- target and room precision/recall/F1 separately
- fully-correct case rate
- clarification decision accuracy, precision and recall
- explicit per-language breakdown
- context coverage and a gate prediction that is clearly labelled as extraction-only

For v1, material/replacement, quantity and unit accuracy are **unmeasurable** because the gold labels do not contain those fields. They are included in the v2 benchmark.

## Context audit

The historical evaluator supplied three fictional quotation lines and an empty catalogue. Only 23/55 cases had a unique target line available in that context; 32/55 gold targets were not uniquely resolvable from the supplied lines. This is a benchmark/context defect, not a model success or failure. The service now defaults to minimal model context and performs tenant-scoped deterministic resolution after extraction; full context remains available explicitly for historical comparison.

## Controlled generation diagnostics

Six fixed fictional cases were run with the installed model:

- full context, `num_predict=350`: operation-type F1 0.500; target F1 0.500
- full context, `num_predict=1200`: operation-type F1 0.500; target F1 0.500
- no quotation context, `num_predict=350`: operation-type F1 0.571; target F1 0.571

All 18 responses ended with `done_reason=stop`. This does not support truncation as the primary cause. Current generation settings are temperature 0, `think=false`, `num_ctx=4096`, no retry, and a 45-second timeout. The JSON schema permits an empty operation list, so it does not force a non-empty proposal.

## Error decomposition

The improved run's largest categories were operation-type errors (23 cases), room errors (19), target errors (6), and clarification-decision errors (1). The Telugu and Romanized Telugu slices remain materially weaker than English/Hinglish. Catalogue ambiguity, unsupported rates and missing rooms are genuine clarification cases and must not be counted as model failures.
